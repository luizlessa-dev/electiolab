## 📋 Setup Steps

### 1️⃣ **Enable Slack Notifications**

1. Go to **Slack Workspace Settings** → **Apps & integrations** → **Incoming Webhooks**
2. Click **Add New Webhook to Workspace**
3. Select a channel (e.g., `#security-alerts`)
4. Copy the webhook URL
5. Add to Vercel environment variables:
   ```
   SLACK_SECURITY_WEBHOOK=https://hooks.slack.com/services/T.../B.../...
   ```

### 2️⃣ **Enable Email Notifications**

Email uses **Resend** (free tier available):
1. Go to https://resend.com/ and create account
2. Get your API key from dashboard
3. Add to Vercel environment variables:
```
RESEND_API_KEY=<your-api-key-from-resend>
ADMIN_EMAILS=admin@example.com,another@example.com
```

### 3️⃣ **Apply Security Alerts Migration**

```bash
# Copy migration SQL
cat supabase/migrations/20260930120000_security_alerts_table.sql

# Paste in Supabase SQL Editor and run
# Result: security_alerts table with RLS policies
```

### 4️⃣ **Verify Cron Job**

In `vercel.json`, check that this exists:
```json
{
  "path": "/api/cron/security-alerts",
  "schedule": "*/5 * * * *"
}
```

### 5️⃣ **Test Alerts (Optional)**

Trigger a test alert manually:
```bash
# Simulate auth failures
# (This would need to be done in Supabase or by making auth requests)

# Or test the cron endpoint directly
curl -X POST http://localhost:3001/api/cron/security-alerts \
  -H "X-Cron-Secret: $CRON_SECRET"
```

## 🔍 Monitoring

### **View All Alerts in Supabase**
```sql
-- Recent alerts
SELECT * FROM security_alerts
WHERE created_at > now() - interval '24 hours'
ORDER BY created_at DESC;

-- Unresolved critical alerts
SELECT * FROM security_alerts
WHERE severity = 'critical' AND resolved = false
ORDER BY created_at DESC;

-- Count by type
SELECT type, COUNT(*) as count
FROM security_alerts
WHERE created_at > now() - interval '7 days'
GROUP BY type;
```

### **Resolve Alerts Manually**
```sql
UPDATE security_alerts
SET resolved = true, resolved_at = now()
WHERE id = 123;
```

## 🚨 Response Procedures

### **Auth Brute Force (5+ failures)**
1. Review IP in `auth_failure_logs`
2. Check if legitimate (e.g., user forgot password)
3. If attack:
   - Add to WAF blocklist
   - Notify user if their account
   - Monitor for escalation

### **Rate Limit Abuse (100+ attempts)**
1. Identify API key/IP
2. Check if legitimate load spike
3. If abuse:
   - Revoke API key
   - Implement backoff in client
   - Consider IP-based throttling

### **Critical Alert (10+ auth / 200+ rate limit)**
1. Immediate notification (Slack + Email)
2. Manual review required
3. Consider temporary IP block
4. Check if coordinated attack

     --data '{"text":"Test"}' \

   - Check `ADMIN_EMAILS` format

3. **Check Cron:**
   - Review Vercel deployment logs
   - Verify `CRON_SECRET` matches

4. **Check Migration:**
   ```sql
   SELECT * FROM security_alerts LIMIT 1;
   ```
