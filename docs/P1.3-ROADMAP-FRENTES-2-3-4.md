## FRENTE 3: P1.3.3 — Real Social Media Signals

### Escopo
- Scrape posts de candidatos (Instagram, TikTok, Twitter/X)
- Calcular engagement score por candidato (likes, shares, comments)
- Feed novo: "Tendência de Interesse" (engagement proxy vs poll average)
- Timeline: 4–6h (design + implementation)

### Schema Supabase

```sql
-- Nova tabela: candidate_social_metrics
CREATE TABLE candidate_social_metrics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID REFERENCES candidates(id) ON DELETE CASCADE,
  platform VARCHAR(20), -- 'instagram', 'tiktok', 'twitter'
  handle VARCHAR(255),
  followers_count INTEGER,
  posts_last_7d INTEGER,
  engagement_rate DECIMAL(5,2), -- % (likes+comments)/followers
  avg_likes_per_post INTEGER,
  last_scraped_at TIMESTAMP DEFAULT now(),
  created_at TIMESTAMP DEFAULT now(),
  updated_at TIMESTAMP DEFAULT now()
);

-- Nova tabela: social_engagement_history (time series)
CREATE TABLE social_engagement_history (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE,
  platform VARCHAR(20),
  engagement_rate DECIMAL(5,2),
  followers_count INTEGER,
  created_at TIMESTAMP DEFAULT now()
);

-- View: daily_social_trend (agregado por candidato)
CREATE VIEW daily_social_trend AS
SELECT 
  c.id as candidate_id,
  c.name,
  DATE(seh.date) as date,
  AVG(seh.engagement_rate) as avg_engagement_rate,
  COUNT(DISTINCT seh.platform) as platforms_tracked
FROM social_engagement_history seh
JOIN candidates c ON c.id = seh.candidate_id
GROUP BY c.id, c.name, DATE(seh.date)
ORDER BY date DESC, avg_engagement_rate DESC;
```

### Scraper Strategy
- **Tools:** Playwright (Instagram/TikTok) + API Twitter (X)
- **Frequency:** Daily cron (similar a poll ingestion)
- **Scope Phase 1:** Top 30 presidential candidates (high-volume)
- **Scope Phase 2+:** Governors, senators (if time)

### API Endpoints
- `GET /api/v1/candidates/:id/social` → últimas 7 dias engagement
- `GET /api/v1/social/trend?position=PRESIDENTE&date=2026-08-19` → agregado daily

### Dashboard Widget
- "Tendência de Interesse (Social Media)" — gráfico de engagement_rate over time
- Comparar vs poll average: "Está crescendo nas redes?"
- Disclaimer: "Engagement ≠ Voto"

### Bloqueadores

## FRENTE 4: P1.3.4 — Financial Tracker Real-Time

### Escopo
- Monitorar gastos de campanha **2026 ao vivo** (CEAP, TSE)
- Alertas: anomalias (spike repentino, fornecedor suspeito)
- Integração: dashboard mostra gasto acumulado + rate por candidato
- Timeline: 3–4h (design + cron setup)

### Schema Supabase

```sql
-- Nova tabela: campaign_finances
CREATE TABLE campaign_finances (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE,
  source VARCHAR(50), -- 'ceap', 'tse', 'tribunal'
  amount_spent DECIMAL(18,2) -- BRL
  category VARCHAR(100), -- ex: 'publicidade', 'transporte', 'pessoal'
  supplier_name VARCHAR(255),
  supplier_cnpj VARCHAR(14),
  description TEXT,
  document_url TEXT, -- link pro comprovante
  created_at TIMESTAMP DEFAULT now(),
  updated_at TIMESTAMP DEFAULT now()
);

-- Aggregate: campaign_finances_daily
CREATE VIEW campaign_finances_daily AS
SELECT 
  c.id as candidate_id,
  c.name,
  DATE(cf.date) as date,
  cf.source,
  SUM(cf.amount_spent) as daily_total,
  AVG(cf.amount_spent) as avg_transaction
FROM campaign_finances cf
JOIN candidates c ON c.id = cf.candidate_id
GROUP BY c.id, c.name, DATE(cf.date), cf.source
ORDER BY date DESC;

-- Anomaly table (flagged by cron)
CREATE TABLE finance_anomalies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID REFERENCES candidates(id),
  anomaly_type VARCHAR(50), -- 'spike_high', 'unusual_supplier', 'undisclosed'
  severity VARCHAR(20), -- 'low', 'medium', 'high'
  description TEXT,
  flagged_at TIMESTAMP DEFAULT now(),
  reviewed_by_user BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT now()
);
```

### Data Sources
1. **CEAP** (Câmara) — deputados federais, atualizado diariamente
2. **TSE** — candidatos (pres, gov, sen), lag ~48h
3. **Tribunais estaduais** — governadores estaduais (se aberto)

### Cron Job: Finance Ingester
```
Schedule: Daily 02:00 UTC (após publicação TSE/CEAP)
Job: `crons/ingest-campaign-finances.ts`
  1. Fetch CEAP API (últimas 24h)
  2. Fetch TSE API (últimas 48h)
  3. Insert/update em campaign_finances
  4. Detect anomalies (spike > 3σ, novo supplier)
  5. Log flagged anomalies em finance_anomalies
```

### Dashboard Widget
- "Gastos de Campanha 2026" — stacked bar (daily spend by category)
- "Ranking Gastos" — top spenders (PRES, GOV, SEN)
- "Alertas Anomalias" — last 10 flagged (com severity color-coded)

### API Endpoints
- `GET /api/v1/candidates/:id/finances` → histórico completo
- `GET /api/v1/candidates/:id/finances/anomalies` → flags + context
- `GET /api/v1/finances/ranking?position=PRESIDENTE&date=2026-08-19` → top spenders

### Bloqueadores
- ⚠️ TSE publicou gastos 2026? (peut-être lag até set/2026)
- ⚠️ CEAP API rate-limit (precisa de batching?)
- ⚠️ Tribunal estaduais API (nem todos oferecem)

# SCHEMAS CONSOLIDADOS — F3 + F4

## F3: Social Media Signals — Schema Completo

```sql
-- Tabela principal: candidate_social_metrics
CREATE TABLE IF NOT EXISTS candidate_social_metrics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID NOT NULL REFERENCES candidates(id) ON DELETE CASCADE,
  platform VARCHAR(50) NOT NULL, -- 'instagram', 'tiktok', 'twitter'
  handle VARCHAR(255) NOT NULL,
  followers_count INTEGER NOT NULL DEFAULT 0,
  following_count INTEGER DEFAULT 0,
  posts_last_7d INTEGER DEFAULT 0,
  posts_last_30d INTEGER DEFAULT 0,
  engagement_rate DECIMAL(5,2) DEFAULT 0, -- % (likes+comments+shares)/followers
  avg_likes_per_post INTEGER DEFAULT 0,
  avg_comments_per_post INTEGER DEFAULT 0,
  avg_shares_per_post INTEGER DEFAULT 0,
  verified BOOLEAN DEFAULT FALSE,
  last_scraped_at TIMESTAMP DEFAULT now(),
  created_at TIMESTAMP DEFAULT now(),
  updated_at TIMESTAMP DEFAULT now(),
  UNIQUE(candidate_id, platform)
);

-- Tabela histórica: social_engagement_history (time series)
CREATE TABLE IF NOT EXISTS social_engagement_history (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID NOT NULL REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE NOT NULL,
  platform VARCHAR(50) NOT NULL,
  followers_count INTEGER,
  engagement_rate DECIMAL(5,2),
  posts_count INTEGER,
  created_at TIMESTAMP DEFAULT now(),
  UNIQUE(candidate_id, date, platform)
);

-- View: daily_social_trend (agregado)
CREATE OR REPLACE VIEW daily_social_trend AS
SELECT 
  c.id as candidate_id,
  c.name,
  seh.date,
  seh.platform,
  seh.engagement_rate,
  seh.followers_count,
  ROW_NUMBER() OVER (PARTITION BY c.id, seh.platform ORDER BY seh.date DESC) as days_ago
FROM social_engagement_history seh
JOIN candidates c ON c.id = seh.candidate_id
ORDER BY seh.date DESC, seh.engagement_rate DESC;

-- Índices
CREATE INDEX IF NOT EXISTS idx_candidate_social_metrics_platform 
  ON candidate_social_metrics(candidate_id, platform);
CREATE INDEX IF NOT EXISTS idx_social_engagement_history_date 
  ON social_engagement_history(candidate_id, date DESC);
```

## F4: Financial Tracker — Schema Completo

```sql
-- Tabela principal: campaign_finances
CREATE TABLE IF NOT EXISTS campaign_finances (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID NOT NULL REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE NOT NULL,
  source VARCHAR(50) NOT NULL, -- 'ceap', 'tse', 'tribunal_estadual'
  amount_brl DECIMAL(18,2) NOT NULL,
  category VARCHAR(100), -- 'publicidade', 'transporte', 'pessoal', 'consultoria', etc
  supplier_name VARCHAR(255),
  supplier_cnpj VARCHAR(14),
  supplier_cpf VARCHAR(11),
  description TEXT,
  document_url TEXT,
  document_id VARCHAR(255) UNIQUE,
  is_verified BOOLEAN DEFAULT FALSE,
  risk_score DECIMAL(3,2) DEFAULT 0, -- 0.0-1.0 (0=low, 1.0=high anomaly risk)
  created_at TIMESTAMP DEFAULT now(),
  updated_at TIMESTAMP DEFAULT now()
);

-- Tabela agregada: campaign_finances_daily
CREATE TABLE IF NOT EXISTS campaign_finances_daily (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID NOT NULL REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE NOT NULL,
  source VARCHAR(50),
  total_spent DECIMAL(18,2),
  transaction_count INTEGER,
  avg_transaction DECIMAL(18,2),
  created_at TIMESTAMP DEFAULT now(),
  UNIQUE(candidate_id, date, source)
);

-- Tabela: finance_anomalies (flagged by cron)
CREATE TABLE IF NOT EXISTS finance_anomalies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id UUID NOT NULL REFERENCES candidates(id) ON DELETE CASCADE,
  date DATE,
  anomaly_type VARCHAR(50), -- 'spike_high', 'unusual_supplier', 'undisclosed', 'duplicate'
  severity VARCHAR(20), -- 'low', 'medium', 'high', 'critical'
  description TEXT,
  amount_involved DECIMAL(18,2),
  flagged_at TIMESTAMP DEFAULT now(),
  reviewed_by_user BOOLEAN DEFAULT FALSE,
  review_notes TEXT,
  created_at TIMESTAMP DEFAULT now()
);

-- Índices
CREATE INDEX IF NOT EXISTS idx_campaign_finances_candidate 
  ON campaign_finances(candidate_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_campaign_finances_supplier 
  ON campaign_finances(supplier_cnpj, supplier_cpf);
CREATE INDEX IF NOT EXISTS idx_campaign_finances_daily_date 
  ON campaign_finances_daily(candidate_id, date DESC);
CREATE INDEX IF NOT EXISTS idx_finance_anomalies_severity 
  ON finance_anomalies(severity, candidate_id);
```

### F4 Ingester Cron Job
```typescript
// File: crons/finance-daily.ts
// Schedule: Daily 02:00 UTC (antes de social-media)
// Logic:
//   1. Fetch CEAP API (últimas 48h, deputados federais)
//   2. Fetch TSE API (últimas 72h, todos os cargos)
//   3. Fetch Tribunal estaduais (if available, governor candidates)
//   4. Insert/update em campaign_finances
//   5. Aggregate → campaign_finances_daily
//   6. Detect anomalies:
//      - Spike: daily_total > (avg_last_30d + 3σ)
//      - Unusual supplier: CNPJ não registrado, endereço suspeito
//      - Undisclosed: valor alto sem descrição
//      - Duplicate: mesmo supplier+amount dentro 24h
//   7. Log flagged → finance_anomalies
//   8. Send alerts (Slack/email) se severity >= high
```

### F4 API Endpoints
```
GET /api/v1/candidates/:id/finances
  Returns: histórico completo de gastos
  Response: [{date, category, amount, supplier, risk_score, is_verified}]

GET /api/v1/candidates/:id/finances/daily-summary?days=30
  Returns: agregado diário (útil pra gráficos)
  Response: [{date, total_spent, transaction_count, avg_transaction}]

GET /api/v1/candidates/:id/finances/anomalies
  Returns: flags + context
  Response: [{date, anomaly_type, severity, amount, description}]

GET /api/v1/finances/ranking?position=PRESIDENTE&date=2026-08-19
  Returns: top spenders (útil pra comparação)
  Response: [{rank, candidate_name, total_spent_ytd, daily_avg, anomalies_count}]

GET /api/v1/finances/suppliers?q=cnpj_or_name
  Returns: supplier risk profile (histórico de transações, pattern)
  Response: [{supplier_name, cnpj, total_transactions, total_amount, risk_profile}]
```
